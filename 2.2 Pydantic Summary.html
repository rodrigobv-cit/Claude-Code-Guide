Pydantic & Claude Tool Calling

Runtime Data Validation & Deterministic Structured Output Specification

How Pydantic Works

Pydantic transforms standard Python type hints into active, compiled runtime validation constraints:

  • Compiled Core Engine: Built on pydantic-core (Rust) for zero-overhead validation loops.
  • Strict vs. Coercive Parsing: Seamlessly parses string representations into native types (e.g., "42" → 42).
  • Native OpenAPI / JSON Schema: Exposes the complete model definition via .model_json_schema().
  • Deterministic Serialization: Clean exports to standard Python dicts (.model_dump()) and JSON (.model_dump_json()).

Enforcing Structured JSON with Claude

To guarantee valid JSON from Claude without syntax deviations, pass Pydantic's JSON schema as an Anthropic tool and mandate its execution using tool_choice:

from typing import Literal
from anthropic import Anthropic
from pydantic import BaseModel, Field

# 1. Define the target schema
class SecurityAlert(BaseModel):
    incident_id: str = Field(description="Format: SEC-XXXX")
    severity: Literal["low", "medium", "high", "critical"]
    affected_services: list[str] = Field(min_length=1)
    recommended_action: str

# 2. Build the Anthropic Tool definition directly from Pydantic
alert_tool = {
    "name": "record_security_alert",
    "description": "Extract structured incident parameters from logs.",
    "input_schema": SecurityAlert.model_json_schema()
}

client = Anthropic()

# 3. Force Claude to execute the tool
response = client.messages.create(
    model="claude-3-7-sonnet-20250219",
    max_tokens=1024,
    tools=[alert_tool],
    tool_choice={"type": "tool", "name": "record_security_alert"},
    messages=[{
        "role": "user",
        "content": "ALERT: DB prod-pg-01 failed health check at 03:00 UTC. High memory pressure."
    }]
)

# 4. Ingest and re-validate raw tool arguments
for block in response.content:
    if block.type == "tool_use" and block.name == "record_security_alert":
        alert = SecurityAlert.model_validate(block.input)
        print(f"Validated [{alert.severity}]: {alert.incident_id}")

Validation Guarantees vs. Required Guardrails

Aspect Guaranteed by Pydantic + Tool Choice Required Developer Guardrail
JSON Syntax ✓ Yes (No trailing commas, valid strings) None
Type Integrity ✓ Yes (Strict type validation/coercion) None
Key Completeness ✓ Yes (Missing keys trigger validation errors) Set Optional[...] = None if input might be absent
Field Documentation ✓ Yes (Exported via model_json_schema()) Write descriptive Field(description="...") definitions
Semantic Factuality ✗ No (LLMs can hallucinate valid types) Source-grounded prompts, context retrieval, system evals
