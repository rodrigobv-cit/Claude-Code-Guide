Where Guidance Belongs

CLAUDE.md, skills, or hooks — three places for three different kinds of rules.

Conventions that apply all the time — things like naming rules or where files go — belong in your CLAUDE.md file. Procedures and reference material tied to a particular kind of task belong in a skill.

There's a third case. A rule that Claude must not be able to skip belongs in a hook, not in either of the above. That's because CLAUDE.md and skills are both instructions that Claude follows, while a hook is code that actually runs. If skipping the rule isn't acceptable, don't leave it up to instruction-following.

📐
Standing conventions
CLAUDE.md
Naming rules, file locations, general "how we do things here." Applies all the time — isn't tied to a specific task.
📋
Task-specific know-how
A Skill
Procedures and reference material. Only relevant when doing that particular kind of work.
🔒
Non-negotiable rules
A Hook
Not an instruction Claude follows — it's code that actually executes. Cannot be skipped, misread, or forgotten.
The core distinction: CLAUDE.md and skills are both just instructions — Claude reads them and (usually) follows them, but it's still "asking Claude nicely." A hook is different in kind: it's actual code that runs at a defined point (e.g. before a tool call), so it can enforce a rule mechanically rather than relying on Claude choosing to comply.

The test to apply: "Is it acceptable for this rule to be skipped, misread, or forgotten?"

If yes CLAUDE.md or a skill is fine.
If no It belongs in a hook, because only a hook can guarantee the rule always holds, regardless of what Claude decides to do.
