Why Specificity Matters

Telling an LLM to simply "follow PEPs" is too vague and can lead to obsolete or conflicting patterns. Referencing explicit PEP numbers grounds the AI's code generation in precise, modern standards without wasting context tokens.

Key PEPs to Enforce

  • PEP 585 & 604 Modern Type Annotations: Require standard collections for type hints (list[str], dict[str, int]) and the pipe syntax for unions (str | None). Ban legacy imports like typing.List and typing.Optional.
  • PEP 695 Type Parameter Syntax: Require native Python 3.12+ generics syntax (def process[T](item: T) -> T:) and the type keyword for aliases, eliminating the need for TypeVar.
  • PEP 8 & 257 Formatting & Docstrings: Enforce structural consistency. Require snake_case for functions, PascalCase for classes, and mandate Google-style or Sphinx-style docstrings for all public interfaces.
  • PEP 621 Project Metadata: Ensure the AI understands that all project dependencies, build configurations, and tool settings (like Ruff or Pytest) must strictly reside in pyproject.toml.
  • PEP 634 & 701 Modern Idioms: Encourage Structural Pattern Matching (match / case) over complex if/else chains, and utilize formalised inline f-strings for cleaner string interpolation.

## PEP & Coding Standards

- **PEP 8 (Formatting):** Strictly follow snake_case for functions/variables and PascalCase for classes. Max line length is 88 characters.
- **PEP 257 (Docstrings):** Required for all public functions, classes, and modules using Google-style conventions.
- **PEP 585 & 604 (Modern Type Hints):** Use built-in generic types (`list[str]`, `dict[str, int]`) and pipe syntax for unions (`str | None`). Do NOT import `List`, `Dict`, `Union`, or `Optional` from `typing`.
- **PEP 695 (Type Parameters):** Use native Python 3.12 generic syntax (`def func[T]()`) and type aliases (`type Matrix = list[list[int]]`). Do not use `TypeVar`.
- **PEP 621 (Metadata):** All project dependencies, tools, and build configurations must be read from and written to `pyproject.toml`. Do not create `requirements.txt` or `setup.py`.
- **PEP 634 (Pattern Matching):** Use `match / case` syntax for complex conditional logic and type matching where appropriate.
- **PEP 701 (F-Strings):** Utilize modern f-string syntax, allowing inline quote reuse and multi-line expressions.
